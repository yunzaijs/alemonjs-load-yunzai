# 插件异步故障边界

Yunzai 插件共享一个 Worker。有些插件在初始化期间发起未被 loader 等待的异步任务；任务失败产生的 unhandledRejection 不会进入 loader.load() 的 catch。

Worker 在启动插件之前安装异步拒绝边界。错误堆栈中的实际文件路径必须位于当前 plugins 目录内，才能作为插件故障报告。宿主通过独立的 plugin_fault IPC 消息记录完整堆栈，并把状态标记为“运行中（插件异常: …）”。此类消息不会作为 Worker 启动失败处理。故障标记在新 Worker 启动时清除。

这表示该插件可能部分功能不可用，不代表插件已经恢复、卸载或隔离。当前不会自动重新执行失败任务，以免重复发送消息或修改数据。缺少 Git 等环境问题仍需修复。

未知来源的 Promise 拒绝以及未捕获的同步异常保持致命退出语义；同步异常后继续运行无法保证共享状态一致。此边界适用于 Node 默认的未处理拒绝模式，显式启用 --unhandled-rejections=strict 会先触发致命异常。死循环、进程主动退出和内存耗尽也不属于此边界的恢复范围。

若需覆盖上述故障，应进一步将插件置于独立进程，并设计跨插件状态、事件、定时任务与 Bot API 的通信协议；不能用全局吞掉 uncaughtException 替代隔离。

验证：tests/plugin-faults.test.mjs 使用真实 Node 子进程，覆盖插件异步拒绝后其他任务继续执行、未知拒绝及同步异常退出、插件目录归因边界。
