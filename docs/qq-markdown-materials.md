# QQ Markdown 图片素材与缓存

适用于 `alemonjs >= 2.1.113`、`@alemonjs/qq-bot >= 2.1.39`。加载器接入框架的 `useMedia` 素材接口，上传后的 `qqbot-media://image/v1/...` 引用写入 Markdown，图片、正文与按钮可在同一条消息中发送。无需插件逐个适配，也无需图床。

## 官方约束

来源：[QQ 官方素材管理文档](https://bot.q.qq.com/wiki/develop/api-v2/server-inter/message/material-management.html)，核对日期：2026-10-22。

| 项目 | 官方约束 | 加载器处理 |
| --- | --- | --- |
| 单图大小 | 不超过 10 MB | 按 SDK 的 10 MiB 字节上限预检，SDK 再次验证 |
| 格式 | PNG、JPEG、GIF、WebP | 检查文件头；SDK 检测实际 MIME；生成匹配扩展名 |
| 素材数量 | 每个机器人 100 张，可删除释放 | 自有素材最多 50 张，新建前分页查询全机器人当前占用 |
| 机器人归属 | 引用绑定机器人，不能跨机器人复用 | 以 BotId 分区并校验上传/查询结果的 owner；主动发送明确指定 BotId 和目标 |
| 素材有效期 | 最后一次成功引用起滑动 90 天 | 只在成功回执后延长本地期限；新建前查询时采用官方 expiresAt |
| 上传任务 | upload_id 有效 4 小时 | 由 SDK 即时 prepare、PUT、complete，不持久化中间任务 |
| 预签名 URL | expires_in 指定有效期 | 仅交由 SDK 直传，不缓存预签名 URL 或 preview_url |
| 删除 | 立即停止新引用，已发消息不受影响 | 淘汰前排除当前消息用到的全部素材 |

SDK 负责 MD5、SHA1、预签名上传、ETag 校验以及 complete。加载器不自行拼接鉴权头，也不向图片下载或 COS 上传转发机器人令牌。

## 图片尺寸标注

QQ 的 Markdown 图片语法是 `![替代文字 #宽px #高px](url)`，尺寸不能省略。只写 `![替代文字](url)` 时：

- 安卓客户端不按图片解析，直接显示替代文字（用户看到的就是 `[图片]`）；
- 桌面端能解析，但会按默认宽度压成一条，且常伴随「请求第三方失败」提示。

因此加载器写出的引用固定带 `#0 #0`，两处都取 0 表示按原图比例自动缩放。替代文字统一用「图片」，不影响显示。

## 复用与记忆

- SHA-256 比较图片真实字节，文件名不同但内容相同会复用；同一路径或 URL 的内容变化会新建素材。公网 URL 每次读取内容再比对，不把 URL 不变视为图片不变。
- 每条记录包含内容指纹、机器人归属、素材 ID、引用、成功发送次数、最近成功使用时间和预计失效时间。每条成功消息对其中每张不同图片计一次使用；一条消息内重复引用也只上传一次、计一次。
- 命中有效记录时直接发送引用，不调用素材上传或列表接口。新建前查询当前全量有效素材，移除本地已失效记录，核对平台总额。
- 重启后读取持久记录；每次上传、删除和成功发送后原子替换记录文件。不会持久化图片字节或临时预览链接。缓存损坏时仅管理之后新建的素材，不接管、删除身份不明的远端素材。

缓存目录是机器人进程工作目录下的 `data/load-yunzai/qq-materials/`，每个 BotId 对应一个 SHA-256 文件名的 JSON 文件，文件权限为 `0600`。目录受 Git 忽略。保留此目录可跨加载器重启继续复用；不要在机器人运行时手动改写文件。

## 配额与淘汰

50 是加载器自有素材的管理预算，不是官方限制，也不是“发送 50 次后再上传”。同图只要仍有效，就持续复用。

新增图片前，若自有数量已达 50 或全机器人数量已达 100，只从本地记录且官方仍有效的自有素材中选取淘汰对象。优先淘汰七天未成功使用的素材，再按累计成功使用次数从少到多、最近使用时间从旧到新选择。当前消息即将用到的素材全部受到保护。这样高频固定图片可留存，持续变化的面板也不会无限占用空间。

其他插件的素材计入总额但不会被删除。若没有可安全淘汰的自有素材，则退回独立图片发送；不会为腾空间清空机器人素材库。

同一个加载器主进程内，按机器人串行完成准备、发送与淘汰，不同机器人独立；相同图片的并发请求会复用前一次上传。此目录和队列不是多主进程分布式锁，同一机器人应由一个加载器主进程管理；其他进程或插件的同时上传仍可能竞争官方总额，平台拒绝时走准备失败回退。

## 发送与异常

正常路径保留原有消息段顺序：图片转换为 Markdown 图片引用，文字、原有 Markdown 和按钮一起发送。原有 Markdown 内的公网图片链接不改写。

为控制单次内存占用，加载器每次最多准备 50 个图片段、合计最多 20 MiB；这是本地处理预算。超出预算、素材上传/查询失败、存储不可写、未取得准确机器人上下文、含音视频或开启 `markdownToText` 时，使用原有发送路径。图片与 Markdown 分开时，只有按钮的消息仍补充“请选择操作”正文。

收到明确的素材不存在、过期或引用归属无效错误（40035008、40035009、40035010），删除本次使用的自有缓存素材、重新准备后最多重发一次。第二次失败直接报告失败。每次实际上传使用新的文件名，避免 SDK 内部缓存返回已在外部删除的旧引用。

上传/准备失败发生在发送前，可以安全改用独立图片发送；消息已进入发送阶段后，超时、断线、普通拒绝或结果为空不会触发自动降级重发。成功发送后即使本地统计写入失败，也不会将它伪装成发送失败并重试。

## 验证边界

自动测试覆盖重启复用、内容变化、机器人隔离、并发同图、成功计数、过期更新、50/100 张配额、自有淘汰、未知素材保护、大小与格式拒绝，以及桥接层 Markdown/按钮生成、定向主动发送、明确失效重建、超时不重试和准备失败回退。

自动测试使用模拟平台接口；真实 QQ 客户端显示、线上权限和真实 COS 上传仍需真实机器人验证。
